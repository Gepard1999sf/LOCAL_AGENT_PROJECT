# Установка CodeWhale Desktop

CodeWhale Desktop — программа для Windows, в которой работает локальный агент CodeWhale.
Агент уже встроен в установщик. Отдельно нужна только **Ollama** — она запускает языковую модель
на вашем компьютере.

Что нужно:

- Windows 10 или 11, 64-битная;
- интернет на время установки (скачать установщик, Ollama и модель);
- несколько гигабайт свободного места под модель.

## 1. Скачайте установщик

1. Откройте страницу релизов:
   <https://github.com/Gepard1999sf/LOCAL_AGENT_PROJECT/releases/latest>.
   Если репозиторий закрытый, сначала войдите в свой аккаунт GitHub.
2. Прокрутите вниз до раздела **Assets**. Если он свёрнут, нажмите на слово **Assets**.
3. Нажмите на файл **`CodeWhale-Desktop_<версия>_x64-setup.exe`**. Начнётся загрузка.

Какой файл выбрать:

| Файл | Для кого |
| --- | --- |
| `CodeWhale-Desktop_<версия>_x64-setup.exe` | **Подходит почти всем.** Ставит программу только для вашей учётной записи, права администратора не нужны. |
| `CodeWhale-Desktop_<версия>_x64.msi` | Установка для всех пользователей компьютера. Windows попросит права администратора. |

Файлы `Source code (zip)` и `Source code (tar.gz)` — это исходный код, для установки они не нужны.

Если браузер Edge пишет, что файл «обычно не скачивают», наведите мышь на загрузку, нажмите
**«…»** → **«Сохранить»** → **«Показать больше»** → **«Всё равно сохранить»**.

## 2. Установите программу

1. Откройте скачанный `CodeWhale-Desktop_<версия>_x64-setup.exe` (двойной щелчок в папке «Загрузки»).
2. Появится синее окно **«Система Windows защитила ваш компьютер»**. Так Windows SmartScreen
   реагирует на любой установщик без цифровой подписи; наш установщик не подписан.
   Нажмите **«Подробнее»**, затем кнопку **«Выполнить в любом случае»**.
3. В мастере установки нажимайте **Next** («Далее»), затем **Install** («Установить») и **Finish** («Готово»).
   Папку установки менять не нужно.
4. Если на компьютере нет компонента Microsoft Edge WebView2 (в Windows 10/11 он обычно уже есть),
   установщик сам скачает и установит его.

Программа появится в меню **«Пуск»** под именем **CodeWhale Desktop**.

## 3. Установите Ollama и модель

1. Установите Ollama одним из способов:
   - скачайте установщик с <https://ollama.com/download> и запустите его;
   - или откройте PowerShell (меню «Пуск» → наберите `PowerShell` → Enter) и выполните:

     ```powershell
     winget install Ollama.Ollama
     ```

   После установки Ollama работает в фоне: её значок виден в области уведомлений рядом с часами.
2. Скачайте модель. В PowerShell выполните:

   ```powershell
   ollama pull <модель>
   ```

   Вместо `<модель>` подставьте имя модели. Какую модель выбрать под вашу видеокарту — смотрите
   рекомендации в [PROJECT.md](../PROJECT.md). Модель должна уметь вызывать инструменты
   (tool calling) и работать с контекстом от 16k токенов. Скачивание занимает от нескольких минут
   до часа: модели весят несколько гигабайт.
3. Проверьте, что модель скачалась:

   ```powershell
   ollama list
   ```

## 4. Первый запуск

1. Запустите **CodeWhale Desktop** из меню «Пуск».
2. Если появился экран **«Ollama не запущена»**, запустите Ollama из меню «Пуск» и нажмите
   **«Проверить снова»** (программа и сама проверяет каждые 5 секунд).
3. Выберите модель: щёлкните по имени модели (пока модель не выбрана, там «—») в строке
   состояния внизу окна или нажмите
   `Ctrl+K` → **«Управление моделями Ollama»**.
4. Откройте папку проекта, с которой будет работать агент: на панели вверху нажмите на кнопку с
   папкой (сначала на ней написано «Проект не выбран») → **«Открыть папку…»**, или
   `Ctrl+K` → **«Открыть папку проекта…»**.
5. Напишите задачу в поле ввода внизу и нажмите Enter.

Если появился экран **«CodeWhale не запустился»**, нажмите **«Перезапустить»**. Если не помогло,
откройте журнал (см. ниже) и приложите его текст к сообщению об ошибке.

## Portable-версия (без установки)

Рядом с установщиками в каждом релизе лежит архив **`CodeWhale-Desktop_<версия>_x64-portable.zip`**.
Распакуйте его в любую папку (например, на съёмный диск) и запускайте `codewhale-desktop.exe`.
В архиве уже есть агент `codewhale-app-server.exe` и папка `resources` — не разделяйте их.
Нужны только Windows 10/11 с WebView2 (есть по умолчанию) и установленная Ollama. Настройки
и журналы при этом всё равно хранятся в `%APPDATA%\net.codewhale.desktop`. При первом
запуске SmartScreen покажет предупреждение — «Подробнее» → «Выполнить в любом случае».

## Обновление

1. Закройте CodeWhale Desktop.
2. Скачайте новый `CodeWhale-Desktop_<новая версия>_x64-setup.exe` со страницы
   [релизов](https://github.com/Gepard1999sf/LOCAL_AGENT_PROJECT/releases/latest) и запустите его так же,
   как при первой установке.

Новая версия встанет поверх старой, настройки и история сохранятся. Ставьте обновление тем же
типом установщика, что и в первый раз: `setup.exe` поверх `setup.exe`, `.msi` поверх `.msi`.
Чтобы сменить тип, сначала удалите старую версию.

Ollama обновляется сама или командой `winget upgrade Ollama.Ollama`.

## Удаление

1. Откройте **«Параметры» → «Приложения» → «Установленные приложения»**
   (в Windows 10: «Приложения и возможности»).
2. Найдите **CodeWhale Desktop** → **«…»** → **«Удалить»**.
3. В окне удаления можно отметить **«Удалить данные приложения»** (Delete the application data):
   тогда удалятся и настройки программы (папки `%APPDATA%\net.codewhale.desktop` и
   `%LOCALAPPDATA%\net.codewhale.desktop`).

Не удаляются автоматически:

- данные агента CodeWhale — папка `%USERPROFILE%\.codewhale` (её же использует CodeWhale,
  установленный через npm, поэтому удаляйте её вручную, только если он вам не нужен);
- Ollama и модели. Модель удаляется командой `ollama rm <модель>`, сама Ollama — там же, в
  «Установленных приложениях».

## Где лежат настройки и журнал

Пути можно вставить в адресную строку Проводника — Windows сама подставит нужные папки.

| Что | Где |
| --- | --- |
| Настройки программы | `%APPDATA%\net.codewhale.desktop\settings.json` |
| Данные интерфейса (WebView2: черновики, кэш) | `%LOCALAPPDATA%\net.codewhale.desktop\` |
| Программа, установленная через `setup.exe` | `%LOCALAPPDATA%\CodeWhale Desktop\` |
| Программа, установленная через `.msi` | `C:\Program Files\CodeWhale Desktop\` |
| Данные агента CodeWhale (сессии, `config.toml`, навыки) | `%USERPROFILE%\.codewhale\` (или папка из переменной `CODEWHALE_HOME`) |
| Модели Ollama | `%USERPROFILE%\.ollama\models\` |

`net.codewhale.desktop` — идентификатор программы из `codewhale-desktop/src-tauri/tauri.conf.json`.

**Журнал.** Программа не пишет журнал в файл: последние строки хранятся в памяти и видны в окне
**«Журнал CodeWhale»**. Открыть его можно щелчком по цветной точке с состоянием в левом нижнем
углу окна или через `Ctrl+K` → **«Журнал CodeWhale»**. Текст оттуда можно скопировать и приложить к сообщению
об ошибке.

## Для владельца репозитория: как выпустить релиз

Установщики собирает GitHub Actions — workflow [`.github/workflows/release.yml`](../.github/workflows/release.yml).
Он скачивает CodeWhale с его [GitHub Releases](https://github.com/codewhale-hq/codewhale/releases),
сверяет SHA-256, встраивает его в программу и собирает `setup.exe` и `.msi`.

### Релиз по тегу

```powershell
git tag v0.2.0
git push origin v0.2.0
```

Примерно через 20–40 минут на странице
[Releases](https://github.com/Gepard1999sf/LOCAL_AGENT_PROJECT/releases) появится релиз
**CodeWhale Desktop v0.2.0** с обоими установщиками и инструкцией. Ход сборки виден на вкладке **Actions**.

- Версия программы берётся из тега: тег `v0.2.0` → версия `0.2.0`. Файлы в репозитории для этого
  менять не нужно, но для порядка можно обновить `version` в `codewhale-desktop/src-tauri/tauri.conf.json`.
- Формат тега: `vX.Y.Z` или `vX.Y.Z-N` для предварительной версии (например, `v0.2.0-1`).
  Буквы вроде `-beta` не подойдут: установщик MSI принимает только числа.
- Чтобы пересобрать релиз, откройте запуск на вкладке **Actions** и нажмите
  **Re-run all jobs** — файлы в релизе заменятся.
- Чтобы убрать неудачный тег: `git tag -d v0.2.0`, затем `git push origin --delete v0.2.0`
  (и удалите сам релиз на странице Releases).

### Сборка вручную, без релиза

1. Вкладка **Actions** → слева **Release** → справа **Run workflow**.
2. В **Use workflow from** оставьте ветку `main`, при необходимости укажите версию CodeWhale
   в поле `codewhale_version`, нажмите **Run workflow**.
3. Когда сборка закончится (зелёная галочка), откройте запуск: внизу, в разделе **Artifacts**,
   лежат `CodeWhale-Desktop_<версия>_x64-setup.exe`, `.msi` и `*-portable.zip`. Они хранятся 30 дней.

Если в **Use workflow from** выбрать тег (например, `v0.2.0`), ручной запуск тоже опубликует релиз.

### Релиз из ручного запуска, без тега в git

Если пушить теги неоткуда (например, из облачной сессии с правами только на одну ветку), релиз
можно опубликовать тем же ручным запуском: в поле **`publish_tag`** укажите `v0.2.0`. Workflow
создаст тег из выбранной ветки сам (от имени GitHub Actions), соберёт установщики и опубликует
релиз с `setup.exe`, `.msi` и `*-portable.zip`. Требования к формату тега те же, что и выше.

### Обновление встроенного CodeWhale

Версия CodeWhale по умолчанию и её контрольная сумма записаны в начале `release.yml`
(`CODEWHALE_DEFAULT_VERSION`, `CODEWHALE_DEFAULT_SHA256` и `default` у поля `codewhale_version`).
Чтобы перейти на новую версию, поменяйте все три значения. Сумму для `codewhale-windows-x64.exe`
возьмите из файла `codewhale-artifacts-sha256.txt` в нужном релизе CodeWhale.
Для разовой сборки достаточно указать версию в поле `codewhale_version` при ручном запуске:
файл всё равно сверяется с `codewhale-artifacts-sha256.txt` этого релиза.
