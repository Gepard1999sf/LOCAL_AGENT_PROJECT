## 1. Цель

Нужен **удобный и надёжный десктоп-инструмент для работы с локальными ИИ-моделями** через агента
CodeWhale. Он заменяет TUI в PowerShell.

Требования:

- **Локально.** Модели работают в Ollama на этом компьютере, без облака.
- **Агент имеет доступ к компьютеру.** Он создаёт и редактирует файлы, запускает команды
  и работает с подсистемами (git, PowerShell, сборка, Godot и т. д.).
- **Агент безопасен и не удаляет важное.** Опасные действия видны заранее и требуют подтверждения
  человека. Права агента ограничены.
- **Надёжность.** Приложение само запускает и перезапускает агента, переживает сбои
  и показывает понятные ошибки вместо пустого экрана.
- **Windows.** Целевая платформа: Windows 10/11, WebView2, PowerShell 5.1.

Сам агент (CodeWhale) не входит в этот проект. Это open-source агент на Rust,
а приложение работает как его графическая оболочка.

## 2. Архитектура

### 2.1 Модель sidecar

Приложение на Tauri 2 запускает отдельный процесс `codewhale app-server` и общается с ним
по HTTP и SSE через loopback. Интерфейс (React в WebView2) напрямую в сеть не ходит:
все запросы идут через команды Rust. CSP разрешает `connect-src` только `ipc:`.

```text
+------------------------- CodeWhale Desktop (процесс Tauri) -------------------------+
|                                                                                     |
|  WebView2: React 19 UI (src/)                                                       |
|      |  invoke("cw_request" | "cw_subscribe" | "ollama_*" | "runtime_*" | ...)     |
|      v                                   ^  события Tauri: cw-event, cw-stream,     |
|  Rust (src-tauri/src)                    |  runtime-status, runtime-log             |
|    runtime.rs  api.rs  ollama.rs  settings.rs  system.rs  winproc.rs                |
+------+--------------------------------------------------+---------------------------+
       | spawn + Job Object (kill-on-close)               |
       | HTTP + SSE, 127.0.0.1:<свободный порт>           | HTTP 127.0.0.1:11434
       | Authorization: Bearer <CODEWHALE_RUNTIME_TOKEN>  | (статус, список моделей,
       v                                                  |  вариант с num_ctx, выгрузка)
  codewhale app-server --http --host 127.0.0.1 --port N   v
       |   OpenAI-совместимый API (/v1)  ------------->  Ollama  ---> GPU / CPU
       |
       +--> инструменты агента: read / write / edit / bash / ... в папке проекта (workspace)
       +--> данные сессий: %USERPROFILE%\.codewhale (или CODEWHALE_HOME)
```

Главные решения:

- **Токен не покидает Rust.** `runtime.rs` генерирует случайный 256-битный токен и передаёт его
  серверу через переменную окружения `CODEWHALE_RUNTIME_TOKEN`, а не через командную строку.
  `api.rs` подставляет его в каждый запрос.
- **Процессы запускает только Rust.** Webview получает лишь `core:default`, диалоги открытия
  и сохранения, открытие URL и «показать в Проводнике» (`src-tauri/capabilities/default.json`).
- **Чат идёт только через CodeWhale.** Ollama вызывается напрямую только для служебных операций (`ollama.rs`).
- **События** сервер отдаёт как SSE. Rust пересылает их в UI событием `cw-event`, а UI собирает
  из них состояние треда (`store/threads.ts`).

### 2.2 HTTP API CodeWhale, которым пользуется приложение

| Назначение | Маршрут |
|---|---|
| Готовность и версия | `GET /health`, `GET /v1/runtime/info` (вызывает Rust при запуске) |
| Список сессий, поиск | `GET /v1/threads/summary?limit=300`, `...&search=<текст>` |
| Сессии TUI | `GET /v1/sessions?limit=50`, `POST /v1/sessions/{id}/resume-thread` |
| Тред | `POST /v1/threads`, `GET /v1/threads/{id}`, `PATCH /v1/threads/{id}` (модель, название, архив) |
| Ход агента | `POST /v1/threads/{id}/turns`, `POST /v1/threads/{id}/turns/{turn}/interrupt` |
| Поток событий | `GET /v1/threads/{id}/events?replay_limit=4096&progress=true&since_seq=N` (SSE, через Rust) |
| Дублирование, сжатие | `POST /v1/threads/{id}/fork`, `POST /v1/threads/{id}/compact` |
| Контекст | `GET /v1/threads/{id}/context` |
| Подтверждения | `POST /v1/approvals/{id}` с `{ decision: "allow" \| "deny", remember }` |
| Вопросы агента | `POST /v1/user-input/{thread}/{input}` |
| Поиск файлов для `@` | `GET /v1/workspace/files/search?query=...&limit=60` |
| Статистика | `GET /v1/usage?group_by=day` |

Исходники сервера: `crates/tui/src/runtime_api.rs` (`build_router`) в репозитории CodeWhale.

### 2.3 Модули Rust (`codewhale-desktop/src-tauri/src`)

| Файл | Ответственность |
|---|---|
| `main.rs` | Точка входа. В release не показывает консоль (`windows_subsystem = "windows"`). |
| `lib.rs` | Сборка Tauri: плагины `opener` и `dialog`, состояния `Runtime`, `Subscriptions`, `Settings`. В `setup` фоном запускает CodeWhale. Регистрирует 20 команд. На `RunEvent::Exit` останавливает сервер. |
| `runtime.rs` | Жизненный цикл sidecar. Ищет бинарник: путь из настроек → `codewhale-app-server.exe` рядом с exe → каталог ресурсов → npm (`%APPDATA%\npm\node_modules\codewhale\bin\downloads\codewhale.exe`) → `PATH`. Выбирает свободный порт, генерирует токен, задаёт `cwd` = папка проекта, `CODEWHALE_TELEMETRY=0` (если телеметрия выключена), `OLLAMA_BASE_URL=<адрес>/v1` (если адрес Ollama нестандартный), `NO_COLOR=1`, `CREATE_NO_WINDOW`. До 30 с ждёт `/health`. При конфликте порта делает вторую попытку на новом. Запуск однопоточный (`start_lock`), неожиданный выход сервера распознаётся. Ведёт кольцевой журнал на 500 строк stdout/stderr (байты читаются как lossy UTF-8, чтобы cp866/cp1251 не обрывали чтение). Устаревший `~/.codewhale/run/daemon.owner.json` переименовывается, если его PID мёртв или переиспользован. Команды: `runtime_start`, `runtime_restart`, `runtime_status`, `runtime_logs`. |
| `api.rs` | `cw_request` проксирует запросы: разрешены только `/v1/*` и `/health`, без `..`, таймаут 120 с, ошибки приходят как `HTTP <код>: <сообщение>`. `cw_subscribe` / `cw_unsubscribe` управляют SSE-потоком треда: возобновление с последнего `seq`, переподключение с задержкой от 0,5 до 10 с, отбрасывание `model.tools.snapshot` (~36 КБ на шаг), состояние потока в событии `cw-stream`. Есть собственный инкрементальный SSE-парсер по правилам WHATWG с юнит-тестами. |
| `ollama.rs` | `ollama_status` (`/api/version` + `/api/ps`), `ollama_models` (`/api/tags` + `/api/show`: capabilities, родной контекст, `num_ctx` из Modelfile), `ollama_create_variant` (`/api/create` с `num_ctx` от 2048 до 262144 и проверкой имени), `ollama_unload` (`keep_alive: 0`). |
| `settings.rs` | `settings.json` в каталоге конфигурации приложения (на Windows `%APPDATA%\net.codewhale.desktop\`). Значения по умолчанию, глубокое слияние, атомарная запись (tmp + rename). При первом запуске проект по умолчанию — `Desktop\CodeWhale_Workspace`, если такая папка есть. |
| `system.rs` | `gpu_stats` (через `nvidia-smi`), `git_branch`, `path_info`, `codewhale_home_path`. `open_in_editor` запускает VS Code напрямую, без `cmd.exe`, и никогда не открывает `.exe`, `.bat`, `.ps1`, `.lnk` и другие исполняемые типы: для них открывается Проводник. `read_image_b64` принимает PNG, JPEG, GIF, WebP до 4 МБ. `write_export` пишет только `.md`, `.json`, `.txt`. |
| `winproc.rs` | Job Object с `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`: всё дерево процессов сервера завершается при перезапуске и вместе с приложением, даже после его падения. `process_info` сообщает, жив ли PID, и время его создания. Константа `CREATE_NO_WINDOW`. |

## 3. Что уже реализовано

### Запуск и надёжность

- CodeWhale запускается автоматически при старте приложения. Статус запуска виден в строке состояния.
- Бинарник ищется так: путь из настроек → встроенная копия → установка npm → `PATH`.
- Если CodeWhale не запустился, показывается экран «CodeWhale не запустился» с текстом ошибки,
  последними строками журнала, кнопками «Перезапустить» и «Указать путь к CodeWhale».
- Если Ollama недоступна, показывается экран «Ollama не запущена». Проверка повторяется
  автоматически каждые 5 секунд.
- Неожиданный выход сервера распознаётся, и runtime получает статус `failed`. Сам он после этого
  не перезапускается: нужен «Перезапустить».
- Поток событий переподключается сам, догоняет пропущенное с последнего `seq`
  и показывает «переподключение» в заголовке сессии. Если поток оборвался совсем,
  появляется «Повторить».
- Дерево процессов сервера завершается вместе с приложением (Job Object).
- Журнал CodeWhale (stdout/stderr) открывается кликом по статусу в строке состояния, его можно скопировать.

### Чат с агентом

- Ответ модели приходит потоком: Markdown (GFM: таблицы, списки, ссылки), подсветка кода Shiki,
  у каждого блока кода есть копирование и перенос строк.
- Размышления модели сворачиваются в отдельный блок. Вызовы инструментов показываются
  с аргументами, результатом, длительностью, статусом и счётчиком `+/−` для правок.
- Diff правок показывается единым видом или «Бок о бок», с номерами строк.
- Агент может задавать вопросы (`request_user_input`): варианты ответа, свободный текст, множественный выбор.
- Есть кнопка «Стоп» и клавиша Esc для прерывания хода, «Повторить» при ошибке.
  Сообщение можно скопировать, отредактировать и отправить снова.
- Под каждым ответом статистика хода: длительность, входные и выходные токены, ток/с, число запросов к модели.
- Поле ввода:
  - `@` дополняет файлы проекта через поиск сервера;
  - `/` открывает команды: `/new`, `/clear`, `/compact`, `/export`, `/model`, `/tools`, `/settings`, `/help`;
  - можно прикрепить файл (вставляется `@`-упоминание) или изображение (до 4 МБ, вставка из буфера Ctrl+V);
  - история ввода листается стрелками ↑ / Ctrl+↑↓.
- Сжатие истории запускается кнопкой, через `/compact` или меню сессии.

### Подтверждения и безопасность

- Опасные вызовы ждут решения прямо в чате. Карточка подтверждения показывает команду, diff правки
  или содержимое нового файла. Цвет рамки зависит от риска: зелёный, жёлтый (запись), красный (команды),
  фиолетовый (сеть).
- Варианты решения: «Разрешить», «Отклонить», «Всегда в этой сессии» (серверу передаётся `remember: true`).
- Автоподтверждение настраивается по инструментам. По умолчанию сами подтверждаются только чтение
  и поиск (`read`, `grep_files`, `list_dir`, `file_search`), а `edit`, `write`, `apply_patch`, `bash`, `Web`
  ждут человека. Автоподтверждение делает клиент и только для live-событий, никогда для истории.
- **Облегчённый набор инструментов** (по умолчанию): модели передаются только `read`, `write`, `edit`,
  `bash`, `todo_write` (`allowed_tools`). Полный набор включается в настройках.
- Токен сервера недоступен интерфейсу. Прокси пропускает только `/v1/*`. Процессы запускает только Rust.
- «Открыть в редакторе» никогда не запускает исполняемые файлы и скрипты и не использует `cmd.exe`.
- Телеметрия CodeWhale по умолчанию выключена (`CODEWHALE_TELEMETRY=0`).
- Чего **нет**: защищённых путей, удаления в корзину, снимков и отката изменений агента,
  песочницы для `bash`. Сейчас единственный барьер — ручное подтверждение
  (см. раздел 7, «Безопасность доступа к компьютеру»). Приложение не передаёт при создании треда
  `mode`, `permission_posture`, `allow_shell`, `trust_mode`, поэтому действуют значения
  по умолчанию CodeWhale: `mode = agent`, `trust_mode = false`, `allow_shell` берётся из конфигурации CodeWhale.

### Модели Ollama

- Выбор модели в шапке. Бейджи: быстрая (до 5B), рассуждает, вызывает инструменты, понимает изображения.
  Есть предупреждения «без инструментов» и о малом контексте (меньше 16k).
- Панель «Модели Ollama» показывает размер, квантизацию, реальный контекст (`num_ctx`, но не больше
  родного окна модели) и сколько модели в VRAM, с пометкой «часть на CPU».
- «Сделать версию с большим контекстом» создаёт вариант с `num_ctx` 16k–64k. Веса общие,
  место на диске не тратится.
- «Выгрузить из VRAM».
- Вкладка «Контекст» в инспекторе показывает заполненность окна, резерв на ответ, порог сжатия
  и давление на контекст. Если Ollama загрузила модель с меньшим контекстом, чем рассчитывает
  CodeWhale, появляется предупреждение: иначе начало запроса молча обрезается.
- Строка состояния: статус агента, модель, `ctx: использовано / окно`, скорость генерации,
  активные и все вызовы инструментов, ветка git, VRAM, загрузка и температура GPU (NVIDIA).

### Сессии и проект

- Боковая панель группирует сессии: «Сегодня», «Вчера», «Последние 7 дней», «Ранее».
  Поиск идёт по названию и превью, а на сервере ещё и по содержимому.
  Работающая сессия показывает индикатор, сессия, ждущая решения, — значок.
- Сессию можно переименовать (двойной клик), дублировать (fork), экспортировать в Markdown или JSON,
  удалить (на самом деле она уходит в архив).
- Сессии терминала (TUI) можно открыть в приложении.
- Выбор папки проекта: недавние папки и ветка git. Смена проекта перезапускает CodeWhale с новым `cwd`.
  Если агент ещё работает, сначала спрашивается подтверждение.
- Инспектор: журнал вызовов инструментов, изменённые, прочитанные и упомянутые файлы
  (клик открывает файл в VS Code, а если его нет — показывает файл в Проводнике).

### Интерфейс

- Темы: тёмная, светлая, «как в системе». Настраиваются моноширинный шрифт, размер и плотность.
- Палитра команд (Ctrl+K), горячие клавиши (справка: Ctrl+/), переключение сессий Ctrl+1…9.
- Адаптивная раскладка: при ширине окна до 1400 px сворачивается инспектор, до 1000 px — сайдбар.
- Длинная история виртуализирована, события применяются раз в кадр.
- «Использование»: ходы и токены по дням.
- «Данные»: экспорт всех сессий в JSON, массовая архивация, открытие `~/.codewhale/`.

### Тесты и CI (**в работе**, файлы ещё не в git)

- Юнит-тесты Rust для SSE-парсера (`api.rs`).
- E2E-тесты интерфейса на Playwright с подменой Tauri, CodeWhale и Ollama (`codewhale-desktop/e2e/`):

## 5. Сборка и запуск на Windows

### 5.1 Что нужно установить

| Компонент | Версия и примечание |
|---|---|
| Rust | 1.88+ (код использует `let`-цепочки edition 2024), toolchain `stable-x86_64-pc-windows-msvc` через rustup. |
| Visual Studio Build Tools | Рабочая нагрузка «Разработка классических приложений на C++» (MSVC и Windows SDK). |
| Node.js | 20.19+ или 22.12+ (этого требует Vite 8). CI использует Node 22. |
| WebView2 Runtime | В Windows 10/11 обычно уже есть. Установщик подтягивает его сам (`downloadBootstrapper`). |
| Ollama | С моделью, которая умеет вызывать инструменты (`tools`), и контекстом от 16k. |
| CodeWhale | `npm i -g codewhale`, или указать путь к `codewhale.exe` в настройках приложения. |
| Git, VS Code | Не обязательны: нужны для ветки в шапке и «Открыть в редакторе». |

### 5.2 Папка сборки Rust

Файл `src-tauri/.cargo/config.toml` с `target-dir` на диске D: **удаляется** из репозитория
(в рабочей копии он уже удалён). Папку сборки теперь задаёт переменная пользователя.
Выполните один раз в PowerShell и откройте новое окно терминала:

```powershell
[Environment]::SetEnvironmentVariable('CARGO_TARGET_DIR', 'D:\AI\build\codewhale-desktop-target', 'User')
```

Без этой переменной сборка (несколько ГБ) пойдёт в `codewhale-desktop\src-tauri\target`.

### 5.3 Разработка

```powershell
cd codewhale-desktop
npm ci
npm run tauri dev
```

В режиме разработки CodeWhale берётся из пути в настройках, из установки npm или из `PATH`.
Vite работает на порту 1420 (`strictPort`).

Проверки, которые делает CI:

```powershell
cd codewhale-desktop
npx tsc --noEmit
npm run build
cd src-tauri
cargo check
cargo clippy -- -D warnings
cargo test
```

`tauri::generate_context!()` встраивает `../dist` при компиляции, поэтому перед `cargo check`
нужно один раз выполнить `npm run build`.

E2E-тесты (**в работе**):

```powershell

npm install
npx playwright install chromium
npm test
```

### 5.4 Установщик (**в работе**)

```powershell
cd codewhale-desktop
npm run bundle
```

`npm run bundle` сначала выполняет `scripts/prepare-sidecar.ps1` (копирует `codewhale.exe`
в `src-tauri\binaries\`), затем `tauri build --config src-tauri/tauri.bundle.conf.json`.
Установщики NSIS и MSI появляются в `<CARGO_TARGET_DIR>\release\bundle\`.
Если `codewhale.exe` лежит в другом месте:

```powershell

npx tauri build --config src-tauri/tauri.bundle.conf.json
```

## 8. Ollama: решение проблем

### 8.1 Перенос моделей на другой диск

Ollama ищет модели в папке из переменной `OLLAMA_MODELS`. Без неё это `%USERPROFILE%\.ollama\models`.
**Переменная должна указывать на папку, в которой лежат `blobs\` и `manifests\`.** Ни на `blobs`,
ни на папку уровнем выше она указывать не должна.

```powershell
# 1. Скопировать модели (пример: на D:)
robocopy "$env:USERPROFILE\.ollama\models" "D:\AI\ollama\models" /E

# 2. Проверить, что внутри именно blobs и manifests
Get-ChildItem "D:\AI\ollama\models"

# 3. Указать папку для текущего пользователя
[Environment]::SetEnvironmentVariable('OLLAMA_MODELS', 'D:\AI\ollama\models', 'User')
```

Затем **полностью перезапустите Ollama**. Значок в трее → Quit Ollama, убедитесь, что процессов не осталось,
и запустите Ollama снова из меню «Пуск». Новая переменная читается только при запуске.

```powershell
Get-Process ollama* -ErrorAction SilentlyContinue   # после Quit должно быть пусто
ollama list                                         # после запуска модели должны быть на месте
```

Если `ollama list` пуст, `OLLAMA_MODELS` указывает не туда или Ollama не перезапускалась.
Старую папку удаляйте только после проверки.

### 8.2 Ollama не отвечает или приложение пишет «Ollama не запущена»

```powershell
# Отвечает ли API
Invoke-RestMethod http://127.0.0.1:11434/api/version

# Слушает ли кто-нибудь порт 11434 и кто именно
Test-NetConnection 127.0.0.1 -Port 11434
Get-NetTCPConnection -LocalPort 11434 -State Listen -ErrorAction SilentlyContinue | Select-Object OwningProcess
```

- Порт свободен: Ollama не запущена. Запустите её из меню «Пуск» (или `ollama serve` в отдельном окне).
- Порт занят другим процессом, или одновременно запущены приложение в трее и `ollama serve`:
  оставьте один экземпляр.
- Ollama слушает другой адрес (`OLLAMA_HOST`): укажите его в «Настройки → Ollama → Адрес»
  и нажмите «Перезапустить CodeWhale», чтобы агент получил новый `OLLAMA_BASE_URL`.

### 8.3 Журнал Ollama

```powershell
Get-Content "$env:LOCALAPPDATA\Ollama\server.log" -Tail 80
```

В начале журнала после запуска есть строка `server config` с действующими переменными,
включая `OLLAMA_MODELS`. По ней видно, какую папку Ollama на самом деле использует.
Там же видно, сколько слоёв модели ушло на GPU.

### 8.4 Агент «забывает» начало задачи или работает медленно

- **Малый контекст.** Без `num_ctx` в Modelfile Ollama даёт модели малый контекст по умолчанию,
  и приложение помечает это как «4k». Создайте вариант модели: «Модели Ollama» →
  «Сделать версию с большим контекстом». Веса общие, лишнего места на диске это не занимает.
- **Модель не помещается в VRAM.** Если в панели моделей или на вкладке «Контекст» видно «часть на CPU»,
  генерация замедляется. Выберите модель меньше или контекст меньше. Ненужную модель можно выгрузить
  кнопкой «Выгрузить из VRAM».
